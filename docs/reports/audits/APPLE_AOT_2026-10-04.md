# Apple static AOT integration

## Implemented

The isolated bootstrap installs the native-only synchronous fault adapter,
preserves previous SIGSEGV/SIGBUS handlers and fails closed for mismatched
native checkpoints. Explicit no-emitter preparation resolves the circular
dependency between observing ready conventions and linking an image.

The Apple/Bun recorder trains exact musl, BusyBox and Bun 1.4.2 guest files on
Darwin, checks the observed target contract and exported symbols, and seals
recordings, generated assembly and logs. It does not replace the Linux
Python/zlib artifact kit. Xcode can force-load these static images using
`AOT_IMAGE_EXECUTION=1` and `AOT_IMAGES_DIR`. Runtime emission remains compiled
out. The default bootstrap and reference schemes remain non-accelerated.

Build identity is retained in `aot-build.json` and logged at startup, including
source revision/dirty state, image manifest hash, app version and build number.
`/proc/ish/version` includes the same image identity. Existing userlands are not
replaced when installing an app update.

## Bun Crash Fix

The pi import crash was reproduced on the Darwin gadgets and linked AOT
runtime. A refused `DC ZVA` write retried at the preceding SIMD store because
the system-instruction decoder never saved its memory-fault checkpoint.
Musl's `memset` then replayed its alignment/length setup after advancing the
pointer, underflowing the count and zeroing memory past the buffer.

`DC ZVA` now saves its exact guest PC before execution. Code version 11
(Apple ready ABI `589f6cec`) rejects previously generated images. The real
decoder/gadget regression checks fault, retry, pointer/SIMD/NZCV preservation
and the exact 64-byte write for every cache-line offset. It fails against the
previous decoder and passes with the fix. Four repeated offline pi workloads
pass on Darwin gadgets (read/edit/write/bash, zero tool errors). Apple native
fault/layout tests pass at O0/O2; 33 AOT/helper tests also pass.

Physical iPhone Release build 821 was installed with the `DC ZVA` fix,
code version 11 and three accepted static images. Its binary SHA-256 is
`08c528897aa52e8401b606bb8428e922e255003f49e4f0e764fefde27a2f0495`;
image manifest SHA-256 is
`acafa5550be7484d5d4ed0d852c98e53d02bfab7e64ecce26387ac9166d401ff`.
The linked Darwin runtime completed the offline pi workload with 3,357,903
AOT installs and zero emitted segments/units/code. A bounded 90-second device
console capture ended at the capture timeout, not an observed app crash.
This is not repeated physical workload or memory-policy acceptance.

The subsequent TLS fixes below change decoder output again. They require code
version 12 (Apple ready ABI `3333e99b`), newly observed/checked target contracts
and regenerated images. Build 821 does not contain these TLS fixes; no version
12 app has been installed yet. Older images must not be relabelled to bypass
the ABI check. The earlier simulator evidence applies only to code version 10.

An earlier captured iPhone reproduction ended with host SIGKILL. No fresh
Jetsam/native report is exposed by CoreDevice, so its cause is not established.
Earlier evidence instead showed guest SIGABRT followed by host exit code 0.
Neither should be attributed to the new AOT changes, which were not installed
at the time of those reproductions.

For version 12, physical iOS contract observation, static-image execution, native fault recovery,
memory-policy verification, repeated pi workload and performance acceptance are
still required. No stable patch release is justified yet. Simulator and Mac
results do not substitute for these physical-device gates.

## Bun TLS / BAD_DECRYPT Fix

The failure is reproducible under guest Bun 1.4.2 with JavaScript JIT disabled.
TLS 1.2 and TLS 1.3 using X25519 or P-256 succeed, but TLS 1.3 using
`X25519MLKEM768` fails with `BAD_DECRYPT`. Bun `fetch` can instead surface this
as `UNKNOWN_CERTIFICATE_VERIFICATION_ERROR`. System downloaders succeeding
does not make this a certificate-store or network-blocking problem.

An independent native Node oracle reproduces incorrect ML-KEM public keys
from fixed imported private keys. The first differing byte is the first key
byte after the SPKI header. AES/GCM records, SHA-3/SHAKE, conventional key
exchange and HKDF agree with native results.

Two emulator bugs were found:

- The halfword single-structure SIMD decoder used `size & 1` for the low lane
  bit. It must use `size >> 1`; bit zero is reserved for these encodings. Both
  non-indexed and post-indexed LD1-4/ST1-4 are corrected. The old decoder fails
  192 cases in the new native-oracle memory regression. Correcting this lane
  selection resolves the ML-KEM oracle mismatch and failing TLS handshake.
- The hand-written USHL gadget used entire halfword/word shift elements instead
  of their signed low bytes, and general-register variable shifts wrapped
  out-of-range counts. It now uses the existing native SIMD shift macro,
  preserving architectural lane-width, aliasing and inactive-lane semantics.
  This is a separate verified defect; fixing it alone did not resolve TLS.

Validation on the corrected Darwin gadget runtime:

- All six independently generated ML-KEM-768/1024 key derivation fixtures pass.
  Bun 1.4.2 lacks the public `crypto.decapsulate` API, so this fixture does not
  claim standalone decapsulation coverage.
- 24 AES/GCM record cases and six key-exchange/HKDF cases pass.
- Recorded instruction comparisons pass: 206,300 SIMD cases, 2,483,400 integer
  cases and 26,859 SIMD memory cases. These are isolated instruction checks,
  not fused-sequence or fault-recovery coverage.
- Certificate-verified TLS 1.3 succeeds with all three key-exchange groups.
  The test reports the actual negotiated cipher (ChaCha20-Poly1305 on the
  observed server). Bun ignored the requested TLS 1.3 `ciphers` option, so
  earlier repeated requests do not establish nine distinct cipher/group
  combinations. TLS 1.2 AES-128/256-GCM is checked separately with enforced
  and verified cipher selection.
- Bun downloads fd 10.5.0 and ripgrep 15.2.0 from GitHub release URLs, plus
  Hugging Face API data and the models.dev catalog. Both archives have gzip
  signatures, and both JSON responses parse. No verification bypass is used.
- The offline pi read/edit/write/bash workload passes with zero tool errors.
  Apple native layout/fault tests pass at O0/O2 with code version 12.
- The combined host crypto/instruction, fault-status and AOT build/helper suite
  passes 37 tests with 189 assertions.
