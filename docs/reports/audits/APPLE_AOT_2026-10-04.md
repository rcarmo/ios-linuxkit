# Apple static AOT integration

## Implemented

The isolated bootstrap installs the native-only synchronous fault adapter,
preserves previous SIGSEGV/SIGBUS handlers and fails closed for mismatched
native checkpoints. Explicit no-emitter preparation resolves the circular
dependency between observing ready conventions and linking an image.

The Apple/Bun recorder trains exact musl, BusyBox and Bun 1.4.2 guest files on
Darwin, checks the observed target contract and exported symbols, and seals
recordings, generated assembly and logs. It does not replace the Linux
Python/zlib artifact kit. Xcode can force-load these static images using
`AOT_IMAGE_EXECUTION=1` and `AOT_IMAGES_DIR`. Runtime emission remains compiled
out. The default bootstrap and reference schemes remain non-accelerated.

Build identity is retained in `aot-build.json` and logged at startup, including
source revision/dirty state, image manifest hash, app version and build number.
`/proc/ish/version` includes the same image identity. Existing userlands are not
replaced when installing an app update.

## Bun Crash Fix

The pi import crash was reproduced on the Darwin gadgets and linked AOT
runtime. A refused `DC ZVA` write retried at the preceding SIMD store because
the system-instruction decoder never saved its memory-fault checkpoint.
Musl's `memset` then replayed its alignment/length setup after advancing the
pointer, underflowing the count and zeroing memory past the buffer.

`DC ZVA` now saves its exact guest PC before execution. Code version 11
(Apple ready ABI `589f6cec`) rejects previously generated images. The real
decoder/gadget regression checks fault, retry, pointer/SIMD/NZCV preservation
and the exact 64-byte write for every cache-line offset. It fails against the
previous decoder and passes with the fix. Four repeated offline pi workloads
pass on Darwin gadgets (read/edit/write/bash, zero tool errors). Apple native
fault/layout tests pass at O0/O2; 33 AOT/helper tests also pass.

## Remaining Gates

Updated static images and physical iPhone validation are still needed for the
new code version. The earlier simulator and linked AOT evidence above applies
only to code version 10, not the fixed build.

The latest captured iPhone reproduction ended with host SIGKILL. No fresh
Jetsam/native report is exposed by CoreDevice, so its cause is not established.
Earlier evidence instead showed guest SIGABRT followed by host exit code 0.
Neither should be attributed to the new AOT changes, which were not installed
at the time of those reproductions.

Physical iOS contract observation, static-image execution, native fault recovery,
memory-policy verification, repeated pi workload and performance acceptance are
still required. No stable patch release is justified yet. Simulator and Mac
results do not substitute for these physical-device gates.
